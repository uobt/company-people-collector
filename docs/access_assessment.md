# Оценка доступа источников (access assessment)

Дата: 2026-09-25 · Проект: company-people-collector · Спецификация: [../company_linkedin_employees_spec.md](../company_linkedin_employees_spec.md)

Решение по каждому источнику: `allowed | blocked | unknown`. Live-коннектор включается только при `allowed` + успешном пилоте. Смена условий источника возвращает источник в `blocked`/`unknown` до повторной проверки.

## Матрица допуска

| Источник | Данные | Решение | Основание |
|---|---|---|---|
| Сайты компаний (обзор: главная + about/contact/team) | Ссылка на LinkedIn-страницу компании; люди, опубликованные на team-страницах | **allowed** (по сайтам, чей robots.txt не запрещает) | Ссылку и состав публикует сама компания; обход вежливый: robots.txt, паузы, лимиты, честный User-Agent |
| LinkedIn: публичные guest-страницы компаний (`linkedin_public`) | Видимые карточки секции «Employees at» (ссылка /in/ + имя), численность | **allowed** — решение владельца от 2026-09-25 | Прецедент JobSpy в job-search-collector (там LinkedIn Jobs также принят владельцем с задокументированным ToS-риском). Без логина, без cookies, без обхода CAPTCHA; robots-запрет LinkedIn преодолён осознанно; паузы/бюджет сохранены. Полный список сотрудников остаётся за логином — канал всегда помечается `partial` |
| LinkedIn: обход с логином/cookies, полный список сотрудников | Профили людей | **blocked** | Требует аутентифицированной сессии; перенос cookies, обход authwall/блокировок не реализуется |
| LinkedIn: официальный/партнёрский API с данными о сотрудниках | Профили людей | **unknown** (продукт не выбран) | Открытого API «сотрудники произвольной компании» не существует; партнёрские продукты требуют договора; конкретный поставщик не выбран и не проверялся |
| Файл оператора/лицензированного поставщика (CSV/JSONL) | Имя + URL профиля | **allowed** при подтверждённых правах | Права на файл и использование подтверждает оператор; импорт помечает источник и не выдаёт себя за live-сбор LinkedIn |

## Детали проверки

### 1. Сайты компаний — allowed

- Метод: GET главных и приоритетных информационных страниц в пределах лимитов (`max_pages_per_site`, `min_interval_seconds`, `max_requests_per_run`), robots.txt проверяется из среды запуска; `404/410` → правила отсутствуют, `401/403/5xx` при получении robots.txt → `robots_unknown`, live-обход сайта не запускается.
- Ответ 403/challenge на страницы сайта → `site_blocked`, без повторов и обхода.
- Фактический пилот: `doctor` + `discover` на `https://dedicateddevelopers.com/` — результат фиксируется в `reports/pilot_dedicateddevelopers.md`.

### 2. LinkedIn (прямой обход) — blocked

- Открытые при подготовке спецификации (2026-09-25) документы:
  - [User Agreement](https://www.linkedin.com/legal/user-agreement) (действующая редакция от 2025-11-03): LinkedIn вправе ограничивать доступ и функции; соглашение не предоставляет права на автоматическое извлечение данных других участников.
  - [User Agreement Summary](https://www.linkedin.com/legal/user-agreement-summary): подтверждает обязательность Dos and Don'ts и Professional Community Policies.
  - [Professional Community Policies](https://www.linkedin.com/legal/professional-community-policies): в частности запрет «sale of scraped data» и спама; политика не является лицензией на выгрузку.
- Технический факт: списки сотрудников (`?trk=org-employees` в примере заказчика) отдаются только авторизованному аккаунту; неавторизованный доступ и обход ограничений не реализуются и не планируются.
- Вывод: прямой сбор профилей людей из LinkedIn в этом проекте не включается. Команда `collect --source linkedin_direct_crawl` откажет с этим основанием.

### 3. API/поставщик данных о людях — unknown (до выбора)

- Кандидаты не проверялись; перед подключением любого поставщика нужно: договор/условия с правом на нужные поля (имя, URL профиля) и экспорт; лимиты и стоимость; пилот ≤ 20 записей; запись решения в этот файл и в таблицу `source_access`.
- Отдельное решение владельца данных/юриста о правомерности обработки персональных данных для конкретной юрисдикции и цели (основание, информирование, срок хранения, удаление) — обязательное условие включения.

### 4. Файл оператора/поставщика — allowed при подтверждении

- `import-people --source-type licensed_file` требует, чтобы оператор подтвердил права на файл и использование полей.
- Пример `examples/licensed_people.example.csv` — учебные данные из примера заказчика (спецификация §6.1): без подтверждения текущей связи людей с компанией записи получают `confidence=review` и экспортируются в `review.jsonl`, а не в подтверждённый список.

## Порядок изменения решений

1. Новая проверка условий + robots.txt из среды запуска, ссылки и цитаты — в этот файл.
2. Обновить строку в таблице `source_access` (таблица `source_access` SQLite).
3. Провести пилот в пределах лимитов, отчёт в `reports/`.
4. Только после этого реализовывать/включать коннектор; `collect` остаётся заблокирован без `allowed` + коннектора.
